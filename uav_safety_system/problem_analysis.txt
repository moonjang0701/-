╔═══════════════════════════════════════════════════════════════════════╗
║           현재 브라운 운동 방식의 문제점                                 ║
╚═══════════════════════════════════════════════════════════════════════╝

❌ 문제 1: 비현실적인 가정
   - UAV가 랜덤하게 떠다닌다고 가정 (브라운 운동)
   - 실제 드론은 정해진 경로로 비행함
   - GPS 오차는 있지만 경로 이탈 수준이 아님

❌ 문제 2: 수학적 복잡성
   - Inverse Gaussian, erf 함수 등 복잡한 수식
   - 직관적이지 않음
   - 디버깅 어려움

❌ 문제 3: 부정확한 결과
   - 충돌 확률 0% 또는 100% 극단값
   - 현실과 맞지 않음
   - 파라미터 조정 어려움

❌ 문제 4: 시간 개념 부족
   - 8시간 운영을 제대로 모델링 못함
   - 시간당 20대 분리 개념 적용 불가
   - 동적 진입/퇴출 불가능

╔═══════════════════════════════════════════════════════════════════════╗
║           Monte Carlo 방식의 장점                                      ║
╚═══════════════════════════════════════════════════════════════════════╝

✅ 장점 1: 현실적
   - 실제 UAV 비행 경로 시뮬레이션
   - 출발지 → 목적지 직선/곡선 경로
   - GPS 오차만 추가 (±5m 정도)

✅ 장점 2: 직관적
   - "충돌했다/안했다" 명확
   - 시각적으로 이해 가능
   - 디버깅 쉬움

✅ 장점 3: 정확
   - 시행 횟수 증가 → 정확도 증가
   - 1000번이면 충분히 정확
   - 현실적인 확률값 (5-20%)

✅ 장점 4: 유연
   - 8시간 타임라인 구현 가능
   - 시간당 20대 진입/퇴출
   - 동적 시나리오 가능

╔═══════════════════════════════════════════════════════════════════════╗
║           제안하는 Monte Carlo 구조                                    ║
╚═══════════════════════════════════════════════════════════════════════╝

시뮬레이션 루프 (1000번 반복):
  ┌─────────────────────────────────────────────────────┐
  │ for trial in range(1000):                           │
  │                                                     │
  │   # 1. 8시간 타임라인 생성                            │
  │   timeline = 0 ~ 480분 (8시간)                      │
  │                                                     │
  │   # 2. 시간당 20대 UAV 스케줄 생성                    │
  │   for hour in range(8):                             │
  │       create 20 UAVs with:                          │
  │         - start_time = hour × 60분                  │
  │         - random start position (베이스)            │
  │         - random end position (배송지, ≤1.5km)      │
  │         - flight_time = 5~10분 (거리 비례)          │
  │         - GPS noise = ±5m                           │
  │                                                     │
  │   # 3. 시간 단위 시뮬레이션 (480분)                   │
  │   collision_detected = False                        │
  │   for t in range(480):  # 분 단위                   │
  │       active_uavs = get_active_uavs(t)              │
  │       for uav1 in active_uavs:                      │
  │           for uav2 in active_uavs:                  │
  │               if distance(uav1, uav2) < safe_dist:  │
  │                   collision_detected = True         │
  │                   break                             │
  │                                                     │
  │   if collision_detected:                            │
  │       collision_count += 1                          │
  └─────────────────────────────────────────────────────┘

최종 충돌 확률 = collision_count / 1000

예상 결과:
  - 시간당 20대: ~8-15% 충돌 확률
  - 시간당 30대: ~20-30% 충돌 확률
  - 현실적이고 해석 가능
